# Current image inputs and a fair offline comparison

Current inference consumes **text only**. `boundary.variant_text` and `input_rows` include approved title, `imageDescription`, facts and presentation style; `imageKey` and IDs are not predictive image features. `fusion.build_shared_prefix` renders those strings into token IDs, and `encode_shared_prefix` calls the language model's hidden-state path. `backbone.FrozenBackbone` explicitly records `vision: not used` and loads/evaluates the language backbone. The trained presentation head scores these text-described variants; returned variant/image-caption IDs map the chosen action back to the catalog. No image file is read, image preprocessing runs, pixel tensor is supplied, or vision embedding is consumed by this path.

The current synthetic v2 catalog uses `fictional-descriptor/<variant-id>` keys and invented image descriptions, not a dataset of actual images. Its presentation score measures an invented text-descriptor/style rubric. It is not evidence of visual recognition, actual image quality, or personalized image performance. Titles and image descriptors vary together in existing variants, so their individual contribution is also not isolated.

## Small prospective offline evaluation

Use actual provided/authorized product images before making visual claims. A bounded design could use 20 products with three real views each, with product-disjoint train/validation/test assignment fixed before descriptions or labels are generated. Include detail/in-use/full-product views and some cases where no candidate clearly meets the stated need. Freeze every test profile and image candidate set; use only observable stated preferences/history. Hold product title, price, availability and nonvisual facts constant across each product's candidate images so image choice cannot succeed just through title variation.

1. **Existing text:** current metadata/caption/style fields, retaining their original uncertainty.
2. **Generated image description:** a fixed, profile-blind offline captioner produces one immutable description per image from its pixels. Give it no preference labels, private personas or held-out answer. Cap description length to match the existing-text information budget. Preserve raw captions plus per-image provenance and unsupported-claim flags. Use the same fixed text ranking model/head and compatibility masks as arm 1; this pair tests descriptive input quality under one decision model.
3. **Direct vision reference, if available:** a compatible multimodal model ranks the same actual images for the same observable requests offline. Current inference cannot run this arm. A different vision architecture/weights is a separate reference baseline, not a causal comparison of input formats alone. Record the difference; do not pass differently shaped vision readouts to the existing trained text head.

Obtain blinded judgments from actual images for each fixed preference task: which view best shows the requested visible detail/style, which ties are acceptable, and whether abstention is correct. Keep image captions hidden from judges. Report paired image-choice accuracy/ranking regret, per-preference responsiveness, compatibility, diversity/redundancy of selected views, factual caption precision for visible attributes, and hallucinated/nonvisible material or capability claims. A caption may describe what the image shows without proving a hidden product property. Review failures where fluent descriptions make selection worse.

All captioning, direct-vision inference and judging occur offline. Record their latency/cost separately from the measured page request. The serving path receives precomputed descriptions keyed by image bytes/hash, product/image version and captioner/model/prompt version; image changes invalidate descriptions. No runtime caption call is needed to test this hypothesis. A precomputed caption is still text evidence, not runtime visual understanding or a proven conversion gain.

No Perceptron/Isaac API was called, integrated, or assumed available. This is an evaluation design, not a claim about those providers' current capabilities or pricing.
