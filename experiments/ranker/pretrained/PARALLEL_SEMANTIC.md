# Bounded parallel quality and latency result

The compact-heading intervention repairs the three initial heading truncations, but the independent-field page generator is **not promoted**. The preserved manifest remains better on strict complete-page quality. Native parallelism is real: the separately labeled scale supplement observed six rows emitting together. It made rejected multi-card attempts faster, not usable multi-card pages.

## What actually ran

Frozen pinned Qwen3.5-9B four-bit MLX backbone, unchanged trained decision heads and selected product/image IDs, text descriptions only. Genuine new wording comes from that same backbone. Section grouping remains deterministic. All output caps (64/128/224), greedy sampling, precision and strict factuality/novelty/completion checks stayed unchanged. No UI, dashboard, shopper harness, new integration, paid compute or Perceptron work occurred.

One orchestrator serialized every GPU process. Two isolated agents independently investigated native cache/measurement correctness and copy quality on CPU. The corrected 256-prefill control passed all eighteen matched cache/shape/repeat arms at 6,364,654,164 peak bytes; the earlier stopped observer attempts and original strict 512 mismatch remain preserved. See [native control audit](NATIVE_BATCH_V5_AUDIT.md).

The six-attempt heading diagnosis changed heading messages only: explicit selected-name evidence, a 3–5-word request, no output names/numbers, shared tags only, and no exhaustive framing-word list. All three compact headings sampled EOS within the same 16-token cap; title/badge messages, budgets and raw tokens stayed identical within each pair. Complete-page acceptance improved from0/3 to2/3. No newline stop, extra budget, output rewriting or validator rescue was used. Compact emitted 81 tokens versus 106; instrumented full run wall was27,217 ms. See [paired diagnosis](HEADING_EXPERIMENT.md).

This fixed variant was then selected for the wider comparison on already inspected cases. Within each comparison all factorized widths used identical prompts and 256-token native prefill. The manifest retained its prior prompt/native512 prefill and served as a separate historical quality baseline. Widths increase 1/2/3/6, with order/warmth bias. Single attempts and observed machine memory pressure prevent deployment-latency claims.

## Guard provenance and machine pressure

The default was introduced by commit 1454374 in `backbone.py` and CLI `--memory-gib`; the original README explicitly says MLX allocator budget rather than OS hard guarantee. Visible user/environment instructions provide no separate six-GiB quota. Later benchmark code added a peak-compliance gate. The default backbone remains six GiB; the supplement's seven-GiB choice is explicit, with available-RAM preflight and no within-run auto increase. See [provenance snapshot](MEMORY_GUARD_PROVENANCE.json).

Physical RAM is25,769,803,776 bytes (24 GiB). Available RAM was10.62GBbefore the smaller-prefill work,4.81GBduring the six-GiB model run,11.10GBafter it, and11.46GBafter the supplement. The recorded pressure indicator changed1→2→1. Existing swap use rose from4.88GBto6.21 GB; swap use alone is not current pressure. Process RSS and MLX allocation overlap and must not be added. The configured MLX limit is not a hard ceiling: both failed six-GiB peaks are genuine measured excursions of that experiment setting, rather than proof the 24 GiB machine cannot run this model.

Keep the manifest as the best measured page generator. Universal-heading claims and the Ridge title-factuality failure remain separate release blockers. Do not promote faster invalid multi-card output or describe deterministic grouping as learned. No further native run was launched after this supplement.
