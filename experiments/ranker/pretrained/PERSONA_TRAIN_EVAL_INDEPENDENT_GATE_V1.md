# Persona adaptation: independent evaluation gate

This gate is proposed before candidate fitting and heldout outcomes. It covers the new integration worktree only. The canonical storefront, native cohort and prior checkpoints remain untouched. Synthetic examples are authored rules and preferences, not observed customer behavior or conversion evidence.

The prior telemetry bridge checks a real tensor-preparation consumer with fake CPU vectors; that does not satisfy the requested training loop. The new candidate must execute a real optimizer over TRAIN-only data, change and reload a checkpoint, evaluate frozen heldout predictions, and preserve failures. Reusing verified frozen Qwen catalog representations is valid. Hashed word/character profile features must be described as hashed features: they are not fresh Qwen profile/query encodings, and an adapted CPU head is not an adapted Qwen backbone.

## Data and independence

The strengthened proposed cohort has 200 synthetic sessions in 25 scenario families, four profile groups per family and two sessions per group: 20 families/160 TRAIN sessions in 80 groups and five families/40 heldout sessions in 20 groups. Ten separate public demo people are excluded from fitting and heldout scoring. The split must be frozen before optimization. Group members, stable profile identity, repeated histories, and any cloned examples must stay in one split. Keep exact scenario-family descriptions/templates out of the opposite split and report shared generic wording and semantic vocabulary explicitly. Authored family holdout is stronger than session-only holdout, but still does not establish unseen human behavior. Sessions within a profile are correlated, so report the 20 independent heldout group outcomes alongside the 40-session denominator.

Use separate TRAIN and heldout label files. A trainer that parses one combined private-label file before filtering TRAIN has already read heldout gold. The combined file may remain provenance, but the fitting process should open only TRAIN labels. Freeze configuration, feature vocabulary/normalization, schedule, target construction, checkpoint selection and baseline rules before heldout labels are opened. If there is no validation split, do not use the 40 heldout sessions for early stopping or hyperparameter selection. Repeated experiments on these outcomes are development replay and must be identified as such.

Public profiles contain explicitly authored public background/color preferences and past observed history only. Product and variant IDs from actual past events are legitimate routing information; the current/future chosen target is a separate label. Event/session/persona IDs, display names/roles, labels, rationales, target indices, evaluator goals and private fixture truth must not become inference features. Session time should be represented only through explicitly documented relative recency, with a cutoff before the predicted action. No synthetic occupation or intent may be inferred from a historical product and then presented as observed fact. External purchases such as a sofa have no invented storefront SKU.

## Real feature and optimizer evidence

The actual catalog source is the read-only canonical run `data/ranker/pretrained/actual-store-function-v3-attempt-1` under the original checkout. The integration worktree initially has no native feature run. Reuse must be explicit, with the original report/packet/model/tokenizer/representation pins, the exact sixteen public catalog records and source order, and every tensor/JSON receipt checked through `FeatureStore`. Use `torch.load(..., weights_only=True, map_location='cpu')`. Keep all source archives and original files unchanged.

An old request vector cannot be relabeled as new persona text. If no fresh native extraction occurs, disclose that only the catalog side uses genuine Qwen vectors. Prove TRAIN-only feature fitting and finite tensors, record optimizer update count/losses/nonzero parameter change, reload the saved checkpoint, and exactly reproduce frozen scores. Fail on changed dataset/source/catalog/checkpoint hashes. Freeze checkpoint before heldout inference; freeze all heldout score arrays and eligibility results before opening heldout labels. Include failed and unattempted sessions in the fixed denominator.

## Baselines and primary ranking result

Use the same eligible candidate set and tie-breaking for every arm. Freeze these baselines before outcomes: fixed catalog order; TRAIN global relevance/class prior; the same learned model with no public profile; deterministic shuffled profiles; and most recent/most frequent previously owned storefront product. Keep semantic-query v5 behavior as a separate comparison, because a profile-only CPU head is not a complete substitute for fresh query ranking. A random/one-hot catalog representation ablation is useful if claiming that Qwen representations improve quality: a freely learned projection over sixteen known vectors can otherwise act as arbitrary class codes.

Report top-choice relevance, nDCG@6 or an explicitly defined graded counterpart, target/positive coverage@3 and @6, and duplicate-owned-product@1. Give raw counts and all per-session predictions, not just a mean. For complementarity cases, report useful new recommendation@1/@3 against an offline, independently checked supported label set; recommending the latest purchase must not count as discovering a complementary need. Keep exploration/repeat-purchase exceptions explicit in labels. For equal public query with different profiles, count both halves of the pair correct and show whether profile ablation removes the effect. A single-profile-only popularity shift does not establish personalization.

Before a live candidate claim, require a material improvement over the strongest simple prior/history baseline on the declared primary metric, no hidden exclusion of failures, a positive heldout profile contribution over no-profile/shuffled-profile controls, and no regression on the frozen safety/semantic probes below. A proposed numeric decision rule must be recorded before seeing heldout results. With only twenty independent groups, report uncertainty and group wins/losses; do not imply statistical certainty from forty correlated rows. Failure of this gate preserves the run as an experiment rather than selecting a new threshold after outcomes.

## Independent end-to-end checks

Ranking quality and hard guards are separate measures. Freeze exact-name requests, explicit item-budget ceilings (including equality boundaries), supported versus unsupported hard requirements, zero/one/two eligible-product shortfalls, and conflicting query/profile cases. Exact-name identity and explicit hard constraints take precedence over the profile score. No guard arm may pad ineligible products to six. Unknown delivered price, size, inventory or unsupported attributes must remain unsupported. Language parser gaps stay visible.

For all returned products, require variant IDs/colors/images to be bound to actual catalog facts. Distinguish an explicit public color preference from a hidden target color; validate unknown/unavailable colors and color conflicts. A learned color score cannot invent a variant or imply stock. Report color validity separately from private-label preference agreement.

Validate fresh titles, badges, sections and body copy against the selected product/variant facts, exact price and public color. Include generation provenance and failures; no teacher/label runtime lookup. Existing source-conditioned text heads may be reused only under their declared TRAIN-seen catalog scope. Profile-specific claims require public supporting observations; a synthetic background does not license invented product facts. Preserve six real products where eligible, with explicit shortfalls otherwise. Copy validity alone does not prove relevance.

Finally measure complete useful above-fold readiness separately from full completion in the real browser, with fresh request IDs, actual response/DOM agreement, decoded primary images and visible factual copy. CPU head timing, Qwen rank-only timing, valid JSON, or below-fold completion cannot substitute for that measurement. Native/browser work must wait for the cohort owner's idle window.
