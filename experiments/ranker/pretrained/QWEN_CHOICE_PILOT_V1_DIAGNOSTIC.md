# Public Qwen routing pilot: source and output diagnosis

The completed 20-forward public-demo pilot has a working routing format but weak catalog-order stability. All 20 unrestricted full-vocabulary argmax tokens are members of the A–P routing set; total probability mass on those 16 tokens ranges from **0.999627 to 0.999895**. Thus this is not a case where a restricted softmax merely forces an unrelated next token into a product choice. The assistant `Choice:` prefix and whole-token boundaries are functioning at the observed output position.

Only two of ten people retain the same selected product under catalog reversal, both selecting a bottle. Canonical order chooses organizer five times, bottle twice and tote/lamp/sweatshirt once each. Reversed order chooses blanket/bottle three times each and lamp/mug/pack/lunch box once each. No selected item is a recorded owned store purchase. The latter is a limited public-history check, not a usefulness guarantee.

Two top-logit ties occur: Priya reversed (notebook N and mug P at22.375) and Lena canonical (several products at21.875). Tie selection follows the stored token-ID tie break, consistent with full-vocabulary argmax. The logit grid is coarse enough for exact ties; original pre-cast LM-head dtype was not logged, so this note does not attribute their entire cause to a measured numerical error. Other substantial order changes have nonzero margins and cannot be explained solely by tie breaking.

## Forward-path review

The installed `mlx_lm/models/qwen3_5.py` wrapper calls its `language_model`, whose `TextModel.__call__` first calls `self.model(inputs, cache, ...)`, then `self.lm_head(out)` when word embeddings are untied. The wrapper's `model` property is exactly that same language body. The language body returns its final RMS-normalized hidden states. The pilot calls that body with `cache=None`, slices `hidden[:, -1:, :]`, then applies the same untied LM head. It applies no L2 normalization. The actual checkpoint is untied, and the before/after hashes include the LM-head weight/scales/quantization-offset tensors among all 927 unchanged tensors.

The installed affine `QuantizedLinear.__call__` applies `mx.quantized_matmul` along the final feature dimension and adds an ordinary bias only if present. It has no operation coupling different sequence positions. Consequently the pilot is structurally the last-position equivalent of the full wrapper path. Single-host loading configures no distributed sharding gather. I found no missing final norm, wrong body/wrapper nesting, shifted prediction position or unintended adapter in this source review.

**Actual native numerical/bit parity was not measured.** A last-token-only versus full-sequence quantized GEMM can select different kernels or rounding paths. CPU source inspection and fake-array unit checks cannot prove exact native equality. If needed, a separately authorized tiny parity experiment should compare the actual wrapper and body-plus-head on identical tokens under the same lock, dtype and memory guards, with maximum error/top-two margins recorded. A full-sequence vocabulary tensor can be large; this should not be added silently to the finished pilot.

## Next representation diagnostic

The current two orders change both candidate position and the arbitrary code assigned to each product. They do not isolate code-token prior from list-position bias. A pretrained A–P output row is a code classifier, not a fixed product representation. The broad shopping query, many recent interests and a long catalog also make this a demanding categorical binding task; these results do not establish inadequate Qwen capacity.

The next frozen public-only pilot therefore binds a natural one-token label to each product across both catalog orders and renders factual entries/readable history as plain text. Fifteen labels are exact public product/category nouns. The sweatshirt has no one-token `sweatshirt` or `crewneck` spelling; the parent explicitly permits exact public material label **cotton**, with full name/category retained and its ambiguity disclosed. The notebook label is **notes**, matching “Pocket field notes”; an invented public name is not introduced. Code-to-product mapping and token IDs stay fixed when entries reverse.

This changes labeling and presentation together and is another development diagnostic, not a controlled single-factor quality proof. If useful, an additional formatting-controlled comparison could separate those contributions. No private gold, new fitting, native execution or live promotion was performed by this CPU audit.
