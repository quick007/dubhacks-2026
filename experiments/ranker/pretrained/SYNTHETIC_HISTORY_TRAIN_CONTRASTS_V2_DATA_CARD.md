# TRAIN purchase contrasts v2

This is an explicitly authored synthetic training transform of **160 verified Tiger TRAIN sessions**, with **160 paired counterfactual sessions**, for **320 total TRAIN rows in the original 80 user groups**. It changes no original profile, group split or frozen v1 file. It adds no heldout group and makes no claim about real customers, browser observation or conversion.

Each pair has identical query, background, stated colors, item budget, hard requirements and all other history events. The original external purchase anchor is replaced with a factual purchase of the original primary recommended store product. The new event uses its canonical store name, category, actual preferred variant/color and the original timestamp. Its event ID receives a counterfactual suffix so hypothetical alternative facts do not claim the same persisted event identity. The new profile/session IDs link to the original TRAIN profile and retain its user-group ID.

The private contrast label gives the newly purchased product grade zero, preserves grade zero for previously owned items, and promotes the strongest existing eligible unowned positive alternative(s). No previously zero-grade product is made relevant. All 160 contrasts retain two positive alternatives. This teaches novelty for an addition request without replacement intent; it is not a universal rule against buying another item of the same kind.

## Source and leakage boundary

The generator reads exactly four data files: root's TRAIN-only Tiger projection and provenance receipt, original `labels.train.json`, and the public catalog binding. A runtime file-read guard in the tests enforces this allowlist. It does not read the full 200-profile export, heldout profiles/labels, the new 32-row evaluation, private diagnostic probes or the original scenario recipe. The upstream projection receipt truthfully records mechanical decoding of the full public Tiger export to select the original TRAIN whitelist; no heldout request was retained or analyzed for this transform.

TRAIN labels deliberately choose the counterfactual purchased item. This is label-conditioned synthetic data authoring, documented in the manifest. Runtime inputs contain only a legitimate-shaped public purchase record, not a desired product, relevance score, promotion hint, pair link or rationale. Private labels and pair links stay outside the inference request. This intervention pattern is now TRAIN-seen, so a later matched intervention test measures transfer to new public combinations, not unseen behavior or a new causal law.

## Coverage and validation

Changed purchases cover all 16 actual store products, with eight rows each except blanket, lamp, lunch box and organizer with 16 each. Alternative promotion covers 11 products supported by the original positive judgments. We do not invent extra utility labels to force a uniform promoted-class distribution. Catalog prices, preferred variants and selected colors are checked. Unknown hard constraints fail rather than being dropped; all source TRAIN rows currently have an empty hard-requirement list.

The combined packet preserves all original 160 TRAIN requests and labels as parsed data, then appends the 160 counterparts. `pair-links.json` records source/contrast profile and session IDs, original groups, the changed event and promoted existing positives. `SOURCE_ACCESS_LOG.json`, `TIGER_TRAIN_PROJECTION_RECEIPT.json`, `TRAIN_PUBLIC_FROZEN.json` and the manifest bind source hashes and outputs. The public freeze receipt explicitly says TRAIN labels were read to author the purchases; it does not claim blind public-data collection.

Seven CPU tests cover group/class balance, exact paired context, factual event bindings, ownership/grade changes, price/color/constraint rejection, access isolation, deterministic hashes, source immutability and overwrite refusal. Targeted TypeScript checking also passes. Reproduce into an unused directory with `node scripts/build-synthetic-history-train-contrasts-v2.ts /tmp/new-history-contrasts`; run `node --test scripts/build-synthetic-history-train-contrasts-v2.test.ts`.

The parent Tiger round trip is verified; these new hypothetical rows themselves have not been persisted and exported as another report. They are a separately versioned training transform of that readback. Changed public contexts require their own verified Qwen context features. An old context vector must never be relabeled as the changed purchase. Catalog vectors may remain cached because catalog facts do not change. Freeze model schedules on TRAIN, preserve prior failed candidates, and evaluate the separate frozen cohorts only after predictions/checkpoints freeze. No training, native feature extraction, browser action, database mutation or Git operation is performed by this data builder.
