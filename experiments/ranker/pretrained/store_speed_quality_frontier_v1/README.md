# Prepared speed and quality frontier

CPU-only curated development packet:32 requests,16 public product functions, two
wordings each. Every request retains16 eligible products,6 cards and20 copy fields.
The packet has no model outputs, timings or native quality results. Three wordings
overlap existing TRAIN exactly; it is not an unseen or sealed benchmark.

Only the nested `request` belongs in inference. Outer case IDs encode catalog
indices and are scheduler metadata; relevance labels stay offline. Top-one labels
do not claim all six returned cards are relevant. Budgets and hard constraints
have separate probes. The [independent audit](../STORE_SPEED_QUALITY_FRONTIER_V1_AUDIT.md)
checks public support, parser eligibility and disclosure. The first draft remains
[archived](../store_speed_quality_frontier_draft_01/manifest.json).
