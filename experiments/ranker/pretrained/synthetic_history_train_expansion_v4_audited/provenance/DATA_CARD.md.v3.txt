# Functional public-context TRAIN expansion v3

This packet adds 128 authored synthetic training requests in 64 new groups. It reads the public sixteen-product catalog binding and existing TRAIN-only projection for exact background deduplication. No evaluation packet, private evaluation label, candidate prediction or outcome was read. The original datasets remain unchanged. The public request/annotation draft before validation is retained in `authoring_history/` with `.txt` extensions and is excluded from fitting.

There are four groups per source product, with distinct daily situations and secondary interests. Sixteen pairs reverse the priority of two simultaneous needs. Sixteen change only one observed event type from view to purchase: the same publicly stated conditional priorities then move to the first unmet need. Sixteen keep the purchase history fixed and introduce an explicit replacement request for an owned item. Sixteen hold functional grades fixed while changing color preferences or releasing a hard color restriction. The public fields contain the information needed to interpret each change.

The final public rows contain 61 broad query strings, 64 distinct base backgrounds, 108 distinct background blocks and 78 color-preference lists. `Browse the store` is included. Dates are ordered; history lengths are four to six events, with purchase positions and view/cart distractors varied across groups. Event, session and profile identifiers are excluded from semantic context by the public formatter. No person names, target IDs, grades or rationales are added to the inference DTO. Real source product/variant IDs appear only where they are legitimate observed history facts.

Annotations are separate in `labels.train.json`: grade 3 is the explicit first unmet need, grade 2 a sensible stated secondary need. Every positive satisfies the public item budget and hard color requirements. An observed purchase has grade 0 unless the public background explicitly asks to replace that item. Grade 0 means outside this request's priorities, owned or ineligible; it does not mean the product is universally irrelevant. Preferred variants use the exact available color names and canonical variant IDs; all 48 variants occur as preferred labels. Soft preferences preserve other eligible colors in `acceptableVariantIds`; hard color constraints restrict that set.

The dataset supports ranking or multi-item lexical output. Consumers should read the public `request` only for inference and join labels by external `profileId`. A universal ownership mask or an instruction that purchases can never be recommended would contradict the sixteen explicit replacement rows. A model that ignores grade-2 items also discards the combined-needs supervision. This packet does not prescribe a new model architecture or select a checkpoint.

CPU checks validate all public DTOs, canonical history facts, graded eligibility, ownership/replacement exceptions, exact counterfactual changes, old-TRAIN exact-background nonoverlap and deterministic reproduction. Whole public-context tokenization using the pinned existing Qwen tokenizer is 205–294 tokens, with no truncation and no model load. This is a compact-context check; a consumer adding the full catalog must still preflight its complete prompt separately.

`manifest.json` freezes the final packet. It is ready for independent semantic audit, not a model-quality result or permission to skip that audit before fitting. No GPU, native feature extraction, browser, Git action or fit was performed in this data lane.
